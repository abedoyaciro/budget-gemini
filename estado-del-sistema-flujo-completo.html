Cómo usa el sistema las dos APIs de Gemini
⚡ generate_content (Analizador)

Usado en: make analyze

Llamada stateless: envías todo el contexto en un solo prompt y Gemini responde. No hay sesión ni ID de interacción. Ideal para diagnósticos donde el prompt ya contiene todo lo necesario (snapshot + memoria cargada en Python).

Usa Structured Outputs con Pydantic: Gemini garantiza que la respuesta sea JSON válido que cumple el schema de DiagnosticoFinanciero.

🔄 Interactions API (Aprendizaje + Confirmador)

Usado en: make learn y make confirm

Llamada stateful: Gemini guarda la sesión en su servidor con un interaction_id. Cuando el usuario pide modificar una regla (opción M), el confirmador llama con previous_interaction_id y Gemini recuerda todo el análisis anterior sin tener que reenviar los 128 registros.

Fallback automático: si la interacción expiró en el servidor (Free Tier: 1 día), el sistema reconstruye el contexto desde el historial local guardado en output/historial_interacciones/.
